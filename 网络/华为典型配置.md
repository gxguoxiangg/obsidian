## 以太网接口

### 配置接口速率和双工模式示例

配置接口速率和双工模式可以在自协商或非自协商两种模式下进行：

- 在自协商模式下，接口速率和双工模式由链路两端的接口协商决定，一旦协商通过，链路两端的设备就锁定在同样的双工模式和接口速率。自协商功能只有在链路两端设备均支持时才可以生效。如果协商失败，则接口可能会处于Down状态。
- 当对端设备不支持自协商功能，或者配置自协商后设备无法连通、物理连通后接口出现大量错包或丢包，
- 户可配置本接口工作在非自协商模式下，手动配置接口速率和双工模式，调整接口的速率和双工模式。

![image.png](https://img.imgdd.com/45e6af11-2294-4bf6-a788-7e7ef6a12a29.png)

组网需求：

如图所示服务器群（Server1、Server2和Server3）分别与Switch的接口GE1/0/1、GE1/0/2和GE1/0/3相连，Switch通过接口GE1/0/4上行接入Internet网络。

由于服务器网卡的特殊限制，接口GE1/0/1、GE1/0/2和GE1/0/3只能自协商为半双工模式，在该双工模式下，当业务数据流量较大时将会产生丢包现象；同时，接口GE1/0/1、GE1/0/2和GE1/0/3速率自协商为最大速率1000Mbit/s，当服务器群同时以1000Mbit/s速率对外发送数据时，就会造成出接口GE1/0/4拥塞。用户希望解决数据丢包和拥塞问题。

配置思路：

- 配置接口工作在非自协商模式，避免服务器网卡影响设备接口的最终工作速率。
- 在非自协商模式下强制指定接口双工模式为全双工，避免发生数据丢包现象。
- 在非自协商模式下强制指定接口工作速率为100Mbit/s，避免发生数据拥塞现象。

操作步骤：

```bash
# 创建端口组，将 1/0/1、2、3 加入端口组中
[Switch] port-group portgroup1
[Switch-port-group-portgroup1] group-member G 1/0/1 to G 1/0/3
# 批量配置接口工作在非自协商模式，双工模式为全双工，工作速率为100Mbit/s
[Switch-port-group-portgroup1] undo negotiation auto
[Switch-port-gourp-portgroup1] duplex full
[Switch-port-group-portgroup1] speed 100
```

检验结果：

```bash
[Switch] display interface gigabitethernet 1/0/1
...
Port Mode: COMMON COPPER                                                        
Speed : 100,    Loopback: NONE                                                  
Duplex: FULL,   Negotiation: DISABLE                                            
Mdi   : AUTO,   Flow-control: DISABLE  
...
```

#### 配置静态和黑洞MAC示例

手动配置静态MAC，一般是为了防止假冒身份的非法用户骗取数据，由网络管理员手动在MAC地址中添加合法用户的MAC地址表项。手动配置静态MAC地址表项的数量比较大时，不便于网络管理员维护，此时可以使用端口安全功能实现MAC地址和接口的动态绑定。

```bash
# 添加黑洞mac
[Switch] mac-address blackhole xxxx-xxxx-xxx5 vlan 3
```

链路聚合是指将多条以太网物理链路捆绑在一起成为一条逻辑链路，从而实现增加链路带宽的目的。链路聚合分为手工模式和LACP模式。手工模式下，所有活动链路都参与数据转发并分担流量。

操作步骤：

```bash

[SwitchA-Eth-Trunk1] port trunk allow-pass vlan 10 20

# 配置 Eth-Trunk1 基于源MAC地址与目的MAC地址进行负载分担
[SwitchA] int eth-trunk 1
[SwitchA-Eth-Trunk1] load-balance src-dst-mac
```

#### 配置LACP模式的链路聚合示例

LACP模式可以提高Eth-Trunk的容错性、提供备份功能。LACP模式下，部分链路是活动链路，所有活动链路均参与数据转发。如果某条活动链路故障，链路聚合组自动在非活动链路中选择一条链路作为活动链路，参与数据转发的链路数目不变。

![image.png](https://img.imgdd.com/578b2c15-8a90-4283-a0ac-2a934ef471ae.png)

操作步骤：

```bash
# 创建Eth-Trunk1并配置LACP模式
[SwitchA] interface eth-trunk 1
[SwitchA-Eth-Trunk1] mode lacp

# 将成员接口加入Eth-Trunk1
[SwitchA-Eth-Trunk1] trunkport g 0/0/1 to 0/0/3

# 在SWA上配置系统优先级为100，使其成为LACP主动端
[SwitchA] lacp priority 100

# 在SWA上配置活动接口上限阈值为2
[SwitchA-Eth-Trunk1] max active-linknumer 2

# 配置接口优先级确定活动链路
[SwitchA] int g 0/0/1
[SwitchA-G0/0/1] lacp priority 100
[SWitchA] int g 0/0/2
[SwitchA-G0/0/2] lacp priority 100

# 配置Eth-Trunk1接口允许VLAN10和VLAN20通过
[SwitchA] interface eth-trunk 1
[SwitchA-Eth-Trunk1] port link-type trunk
[SwitchA-Eth-Trunk1] port trunk allow-pass vlan 10 20

# SwitchB 需要需要执行相同的操作
```

#### 配置Super VLAN示例

Super VLAN（VLAN 聚合）的主要功能就是节约IP地址，隔离广播风暴。Super VLAN 下关联多个 Sub VLAN，Sub VLAN之间二层隔离，所有 Sub VLAN 共用 Super VLAN 的 VLANIF 接口IP地址与外界通信，并可以通过该接口三层互通，从而节约IP地址。

![image.png](https://img.imgdd.com/13de1ed6-29d2-4cd1-bdcf-f96a6022082d.png)

组网需求：

某公司拥有多个部门且位于同一网段，为了提升业务安全性，将不同部门的用户划分到不同VLAN中，如图所示，VLAN2或VLAN3属于不同部门，各部门均有访问Internet需求，同时由于业务需要，不同部门间的用户需要互通。

操作步骤：
创建 Super-VLAN4，将VLAN2、加入到 Super-VLAN4中。配置 Super-VLAN4 的 VLANIF，使得底下的用户可以通过Super-VLAN4访问互联网

```bash
[SWA]
# 常规的 vlan 设置


[SWB]
# 配置 Super-VLAN 4 将 VLAN2、3 加入到 Super-VLAN4
vlan batch 2 to 4 10
vlan 4
	aggregate-vlan
	access-vlan 2 to 3
# 在SwitchB的Super-VLAN 4下配置Proxy ARP，使不同部门的用户间三层互通。
int vlanif 4
	ip address 10.1.1.1 24
	arp-proxy inter-sub-vlan-proxy enable
	
```

配置VLAN聚合时，同一个Super-VLAN内的主机使用的是同一个网段的地址并共用一个网关地址，即使是属于不同Sub-VLAN的主机，由于他们同属于一个子网，彼此通信时只会查ARP表项进行转发，而不会通过网关转发，使用Proxy ARP可以使得所有Sub-VLAN建立相应的ARP表项进行互通。

如果只让某些Sub-VLAN之间互通，可以通过在主机上配置静态ARP来实现，将访问目的主机的IP地址与网关MAC地址绑定。

#### 配置路由式ARP代理

处于同一网段的两个用户，被不同的物理设备隔离成两个不同的物理网络，现需要这两个不同物理网络中处于同一网段的用户能互通。
![[Pasted image 20260818164007.png]]
**组网需求：**
如图所示，两台设备通过串行线路相连。两台用户计算机HostA和HostB没有配置默认网关，需要在设备上配置路由式ARP代理，使分处在两个局域网的用户主机能互通。
**操作步骤：**
在连接主机侧的接口上配置路由式ARP代理功能，使得主机发送一个ARP请求（请求目的主机的MAC地址），使得ARP代理功能的设备搜到这样的请求后，会使用自己的MAC地址作为改ARP请求的回应，以此进行数据转发。
```zsh
[DeviceA]
int vlanif 1
	ip address 172.16.1.1 255.255.255.0
	arp proxy enable
int vlanif 2
	ip address 172.17.3.1 255.255.255.0	
ip route-static 0.0.0.0 0 vlanif 1 172.17.3.2

[DeviceB]
int vlanif 1
	ip address 172.16.2.1 255.255.255.0
	arp proxy enable
int vlanif 2
	ip address 172.17.3.2 255.255.255.0
ip route-static 0.0.0.0 0 vlanif 1 172.17.3.1

```

如果主机没有配置默认网关，它又ping一个不同网段的地址，会直接失败，一个包都发不出去。

#### ARP安全

网络中的终端受到攻击，可能会：
- 发送一些目的IP地址不可达的报文
- 发送大量伪造ARP攻击报文，这种报文的源IP地址会不断变化
- 构造大量源IP地址固定的ARP报文进行泛洪攻击

**配置思路：**
1. 配置全局的ARP表项严格学习的功能，限制设备只学习自己发送的ARP请求报文的应答报文。
2. 基于接口配置ARP表项限制功能，限制接口学习ARP表项的最大数目，防止ARP表项溢出。
3. 配置ARP表项固化功能，防止网络攻击者通过发送伪造的ARP报文篡改ARP表项。
4. 配置ARP报文限速，限制设备1秒内处理ARP报文的数量，节省开销。
5. 配置ARP Miss消息限速功能，限制设备1秒内处理ARP Miss消息的数量，节省系统开销

**操作步骤：**
```zsh
# 配置 ARP 严格学习
arp learning strict

# 配置 VLAN10 的 ARP表项限制阈值为20
int g 1/0/1
	portswitch
	arp limit vlan 10 20
# 配置 ARP 表项固化功能
arp anti-attack entry-check fixed-mac enable
# 配置 ARP 报文限速功能
arp anti-attack rate-limit sourip-ip maximum 15
# 配置ARP Miss消息限速功能
arp miss anti-attack rate-limit source-ip 10.10.10.10 maximum 30
arp miss anti-attack rate-limit source-ip maximum 20
arp miss anti-attack rate-limit source-ip 10.20.20.20 maximum 50
```

#### 防止 ARP 中间人攻击

![[Pasted image 20260818183532.png]]
**组网需求：**
管理员希望防止ARP中间人攻击

**配置思路：**
1. 使能动态ARP检测功能；使DeviceA对收到的ARP报文对应的源IP、源MAC、VLAN以及接口信息进行DHCP Snooping绑定表匹配检查，实现防止ARP中间人攻击。
2. 使能动态ARP检测丢弃报文告警功能，使DeviceA开始统计丢弃的不匹配DHCP Snooping绑定表的ARP报文数量，并在丢弃数量超过告警阈值时能以告警的方式提醒管理员，这样可以使管理员根据告警信息以及报文丢弃计数来了解当前ARP中间人攻击的频率和范围。
3. 配置DHCP Snooping功能，并配置静态绑定表，使动态ARP检测功能生效。

### ACL
#### 使用高级ACL限制特定时间访问
![[Pasted image 20260819092415.png]]

**组网需求：**
公司要求禁止研发部门和市场部门在上班时间（8:00至17:30）访问工资查询服务器（IP地址为10.164.9.9），总裁办公室不受限制，可以随时访问。

**配置思路：**
1. 配置时间段、高级ACL和流分类，使设备可以基于时间的ACL，对用户访问服务器的报文进行过滤，从而限制不同用户在特定时间访问特定服务器的权限。
2. 配置流行为，拒绝匹配上ACL的报文通过。
3. 配置并应用流策略，使ACL和流行为生效。

**操作步骤：**
```zsh
[Switch]
# 配置时间段
time-range satime 8:00 to 17:30 working-day

# 配置高级acl
acl 3002
	rule deny ip source 10.164.2.0 0.0.0.255 destination 10.164.9.9 0.0.0.0 time-range satime
acl 3003
	rule deny ip source 10.164.3.0 0.0.0.255 destination 10.164.9.9 0.0.0.0 time-range satime

# 基于高级acl的流分类
traffic classifier c_market
	if-match acl 3002
traffice classifier c_rd
	if-match acl 3003

# 配置流行为
traffic behavior b_market
	deny
traffic behavior b_rd
	deny

# 配置流策略
traffic policy p_market
	classifier c_market behavior b_market
traffic policy p_rd
	classifier c_rd behavior brd

# 应用流策略
int g 1/0/2
	traffic-policy p_market inbound
int g 1/0/3
	traffic-policy p_rd inbound
	
```

#### 配置 OSPF 的基本功能

|:--|:--|:--|:--|
|DeviceA|1.1.1.1|1|区域0：192.168.0.0/24<br><br>区域1：192.168.1.0/24|

|DeviceF|6.6.6.6|1|区域2：172.17.1.0/24|

**组网需求：**
所有设备都运行OSPF，并将整个AS划分为3个区域，其中DeviceA和DeviceB作为ABR来转发区域之间的路由。

**配置思路：**
根据OSPF防环要求，非骨干区域之间的路由信息必须通过骨干区域来转发：
- 所有非骨干区域必须与骨干区域保持连通。
- 骨干区域自身必须要保持连通。
本设备接口发送Hello、Dead和Poll报文的时间间隔要和邻接设备的参数保持一致，否则双方不能建立邻居。

**操作步骤：**

配置OSPF的基本功能
```zsh
[Device A]
router id 1.1.1.1
ospf 1
area 0
	network 192.168.0.0 0.0.0.255
area 1
	network 192.168.1.0 0.0.0.255

# 其他的类似
，，，
```

配置OSPF区域的密文验证模式，Device 之间需要配置相同的密码，否则邻居无法建立。
```zsh
[Device A & B]
ospf 1
area 0
	authtication-mode hmac-sha256 1 cipher passWord
```
